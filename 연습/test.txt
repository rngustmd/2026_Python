1. 이 값을 고정해 두면 코드를 언제, 몇 번을 다시 실행하더라도 항상 동일한 순서와 구성으로 데이터가 분할

2. fit - 모델 학습(훈련) 실행 / predict - 미지의 데이터에 대한 결과 예측

3. 단순히 평균값으로만 예측했을 때 발생하는 오차량 대비, 우리가 만든 회귀모델을 사용했을 때 
오차를 얼마나 줄였는지를 백분율로 환산한 지표

4. 모델이 훈련 데이터의 규칙을 학습할 때, 데이터의 복잡도와 모델의 표현력 사이에서 균형을 맞추지 못해 발생하는 대표
적인 학습 오류 상태 , 
PolynomialFeatures 등으로 특성을 추가 생성하여 고차원 패턴을 표현할 수 있도록 유연성
Ridge나 Lasso 같은 규제(Regularization) 모델을 적용하여 지나치게 비대해진 가중치 의 크기를 수학적으로 강제 축소

5. 입력 데이터의 각 특성을 거듭제곱(2차항)하고 서로 다른 특성끼리 곱한조합(교차항), 
   그리고 절편에 곱해질 1(상수 편향)을 자동으로 계산하여 고차원 특성 행렬을 생성하는 사이킷런의 전처리 변환기(Transformer) 객체를 생성 

6. 표준화 스케일러 객체 생성 / 각 특성의 평균을 0, 표준편차를 1로 맞추는 Z-score 표준화(Standardization) 변환기 객체를 생성

7. 릿지 - 손실 함수에 가중치들의 '제곱합(L2 Norm)'에 비례하는 페널티를 추가
   라쏘 - 손실 함수에 가중치들의 '절댓값의 합(L1 Norm)'에 비례하는 페널티를 추가

8. 수동으로 분리하여 관리할 경우, 코드가 파편화되어 유지보수가 어려워질 뿐만 아니라 테스트 데이터나 교차 검증 검증용 폴드의 정보가 전처리 과정에 유입되는 데이터 누수(Data Leakage)가 빈번하게 발생하기 때문

9. 고정된 단일 분할(Train/Test Split) 방식으로만 모델을 평가할 경우, 데이터가 우연히 한쪽으로 치우쳐 분할되는 편향 이 발생하여 
모델의 실제 일반화 성능을 왜곡하거나 과적합 여부를 정확히 진단하기 어렵기 때문

10.  수동으로 일일이 조정할 경우 비효율적일 뿐만 아니라 최적 성능을 보장하는 조합을 체계적으로 찾아내기 불가능하기 때문
